Microsags

DNA2bit-SAG Tractor documentation

Microsags documents the original integrated DNA2bit-SAG Tractor software: its installation boundary, input contract, workflow modes, output evidence, and reproducibility rules.

Citation

This project currently has no substitute for its versioned source, release archive, and run evidence. The navigation and page organization follow the public SemiBin documentation pattern; Microsags does not use the SemiBin model or algorithm.

Overview

The software accepts a contigs manifest or a paired-reads manifest. A contigs entry can enter the DNA2bit path directly; a reads entry requires the documented read-processing and assembly stage before downstream processing.

Install

conda env create -f environment.yml
conda activate dna2bit-sag-original
JOBS=8 PREFIX="$HOME/.local/dna2bit-sag-tractor" bash install.sh

Usage examples

The examples page follows the short-command style used by SemiBin. Only the confirmed entry points are shown here.

Check the installed command

dna2bit-sag-pipeline --help

Contigs input

Provide a two-column tab-separated manifest with sag_id and contigs. The exact production runner and output contract are documented in the release-specific files.

sag_id<TAB>contigs
SAG_0001<TAB>/absolute/path/SAG_0001.fa

Paired reads input

Provide a three-column manifest with exact headers sag_id, r1, and r2.

sag_id<TAB>r1<TAB>r2
SAG_0001<TAB>/absolute/path/SAG_0001_R1.fastq.gz<TAB>/absolute/path/SAG_0001_R2.fastq.gz

Input preparation

Prepare a deterministic manifest before a run.

Contigs manifest

sag_id<TAB>contigs
SAG_0001<TAB>/absolute/path/SAG_0001.fa

Paired reads manifest

sag_id<TAB>r1<TAB>r2
SAG_0001<TAB>/absolute/path/SAG_0001_R1.fastq.gz<TAB>/absolute/path/SAG_0001_R2.fastq.gz

Checks

  • SAG IDs are unique.
  • All referenced files exist, are non-empty, and are not reused by another row.
  • Paths are absolute or are resolved according to the documented manifest rule.
  • The manifest and its generator are retained with the run evidence.
Length gate

SAG total length below 1000 bp is excluded; exactly 1000 bp is retained.

Workflow modes

Two input modes are documented separately, as in the reference documentation.

Contigs route

contigs manifest
  → length gate
  → DNA2bit classification
  → downstream workflow

Reads route

paired reads manifest
  → read processing and assembly
  → contigs
  → DNA2bit classification
  → downstream workflow

Boundary

These routes have different computational scope. A reads run includes the upstream read-processing and assembly cost; a contigs run does not.

Stage3A

Stage3A groups SAGs that carry an accepted DNA2bit species label.

Documented role

Accepted species labels are aggregated into species-level groups and handed to the deterministic assembly/subassembly path described by the release.

Frozen rules

Detailed member-selection, support thresholds, and quality gates are not reproduced here until they are attached to a versioned release specification.

Stage3B

Stage3B is the downstream branch for SAGs that are rejected or have no accepted DNA2bit label.

Documentation status

The detailed production contract for graph construction, edge definitions, clustering, and group assembly is intentionally left blank in this public guide until a release-specific specification is frozen.

Output and reproducibility

A result is reproducible only when its code, environment, input, database, parameters, and evidence are retained together.

Attempt layout

attempt_001/
├── 00_control/
├── 01_input/
├── 02_dna2bit/
├── 03_stage3a/
├── 04_stage3b/
├── 05_assembly/
├── 06_final_view/
└── receipts/

Evidence

  • Keep the manifest, runner, launcher, database and binaries with SHA256 records.
  • Keep logs, phase receipts, final result metadata and failed attempts.
  • Use a new write-once attempt for a rerun; do not overwrite a previous result.

FAQ

Does Microsags use the SemiBin model?

No. SemiBin is used as a documentation-structure reference only.

Are the databases included?

No. Large external databases are configured separately and are not placed in the GitHub release archive.

Does this page replace a run receipt?

No. The release, manifest, logs, receipts, and final result metadata are the authoritative evidence for a scientific run.
